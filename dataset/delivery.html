Druid SQL Training Set

A thousand training examples and a hundred and fifty validation examples, spread across 69 datasources and twelve prompt formats. Every query was executed against a live Apache Druid 35.0.0 cluster before it was allowed into the file. Nothing here was written from memory.

The split holds whole families back

Holding out one variant of a family would leave its siblings in training with near-identical column names. The split has to be disjoint in vocabulary, not just in table name — so six entire families go to validation, chosen so that validation still exercises every enrichment shape training teaches.

Formats come out even

You asked for an even spread so the serving format stays your choice. Assignment runs most-constrained-example-first, each going to whichever eligible format is currently least used. All twelve land within one example of each other.

Four gates, not one

VALID alone is not enough. JSON_VALUE(json_string_col, '$.k') is accepted by Druid and returns NULL for every row, which is exactly the failure a syntax check cannot see.

EXEC

The completion returns VALID from Druid 35.0.0.

ROWS

It returns at least one row, so the filters match real data.

LINT

It contains the construct its cluster exists to teach.

TRAP

The naive standard-SQL version fails, or returns something different.

Reproducing it

The time anchor is pinned in dataset_meta.json, so regenerating reproduces the seed rows byte for byte. Change the anchor and every datasource needs reloading, because the queries were validated against the data currently ingested.

# ~6-8 GB RAM, on-demand only
cd druid-harness && make up
cd ../dataset && export PYTHONPATH=$PWD/../druid-harness

python3 gen_schemas.py     # specs, seed rows, schema_index.json
python3 load_all.py        # ingest 69 datasources + lookups (~13 min)
python3 generate.py        # draw, split, balance clusters and formats
python3 validate_bulk.py   # four gates against the live cluster
python3 emit_sft.py        # train.jsonl, val.jsonl, dataset_stats.json
python3 make_readme.py     # dataset/README.md, from the artefacts

Worth knowing before you train

The prompt is five to twenty times the answer. If the training config computes loss over the whole sequence, the schema block dominates it and most of the gradient goes into learning to reproduce schemas rather than to write SQL. Masking loss to the completion is worth checking before a long run. That is a call for lora_training.py, which this pipeline does not touch.

Three claims in the spec doc were disproved during this build and are now recorded in its Refuted section. CAST(str AS TIMESTAMP) parses both string timestamp formats correctly, so a trap that assumed only TIME_PARSE works failed validation and was replaced. JSON_VALUE renders JSON booleans as '1'/'0', never 'true'/'false', which silently matched nothing. And probing all 493 column names found exactly two — value and language — that Druid refuses unquoted as identifiers, not just as aliases.

A real bug caught late. Generated join examples referenced their dimension table without that table appearing in the prompt, so the answer was underivable from its own input. Every record is now checked: no query references a table its prompt does not carry.

Approximate aggregators are the house style. The model will reach for APPROX_COUNT_DISTINCT even where an exact count was wanted. Deliberate, per your decision, but worth remembering when you read its output.
